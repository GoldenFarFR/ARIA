## Phase 2 -- Solana (Raydium + Meteora discovery), measure first

- [x] T007 [P2] DONE 25/08 -- Raydium CPMM (`CPMMoo8L3F4NbTegBCKVNunggL7H1ZpdTHKxQB5qKP1C`, verified live via docs.raydium.io AND raydium-io/raydium-cp-swap's own `declare_id!` -- AMM v4 confirmed by the same official doc as no longer the destination for NEW pools since Raydium routes creation to CPMM/CLMM now). First attempt (WS `logsSubscribe` via Helius) was WRONG PROVIDER (operator correction 25/08: "arrete d'utiliser autre chose que le rpc de chainstack") -- redone via Chainstack HTTP polling (`ARIA_SOLANA_RPC_HTTP_POLLING`, same provider/pattern as `pumpfun_curve_tracker.py`), `getSignaturesForAddress(limit=1000)` + a 25-tx sample via `getTransaction`. Real result: 1000 signatures spanned only 20 seconds -> **~180 000 tx/hour, ~4.32M/day total activity**, 0/25 sampled were pool-creation instructions.
- [x] T008 [P2] DONE 25/08, same method -- Meteora DLMM (`LBUZKhRxPF3XUpBCjp4YzTKgLccjZhTSDM9YuVaPwxo`, verified live via web search + official repo MeteoraAg/dlmm-sdk's IDL, creation instruction `initialize_lb_pair`/`initialize_lb_pair2`). 1000 signatures spanned 1 second -> **~3.6M tx/hour, ~86.4M/day total activity**, 0/25 sampled were pool-creation instructions.
- **Decision: NOT building a direct Solana subscription for either program.** The exact creation rate couldn't be pinned down (0/25 samples is too small against activity this dominated by swaps), but that number doesn't change the conclusion: unlike EVM's `eth_subscribe("logs", {topics: [topic0]})`, which filters BY EVENT TYPE at the RPC node itself (a swap on a tracked pool is never even sent), Solana's `logsSubscribe(mentions=[program_id])` has NO equivalent instruction-level filter -- every transaction touching the program (creation or the millions of daily swaps) would be pushed to the client and billed, discarded only after arrival. At 180k-3.6M tx/hour, subscribing directly would reproduce the exact "programSubscribe firehose" shape the 21/08 74GB/day incident (see CLAUDE.md's Solana sourcing section) already forced this dome to replace. Raydium/Meteora discovery stays on the existing funnel-friendly path (whatever aggregator-based discovery the relevant Solana pocket already uses) -- banked, not revisited unless Solana RPC providers ever expose a per-instruction log filter.
- [x] T009 [P2] DONE 25/08 -- decided as part of T007/T008's own conclusion above: no bounded/discriminator-filtered subscription is possible on Solana today (no per-instruction log filter exists at the RPC layer), so the headroom question is moot -- never built.
