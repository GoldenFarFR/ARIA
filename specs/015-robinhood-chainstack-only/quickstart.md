# Quickstart: Validating Robinhood Chainstack-Only Sourcing

Validation scenarios for this feature, mapped to spec.md's Success Criteria. Run from `packages/aria-core/` with the project's `.venv`. No implementation code here -- see `tasks.md` (generated by `/speckit-tasks`) for the build itself.

## Prerequisites

- Working tree on branch `015-robinhood-chainstack-only`, feature merged locally.
- `.venv/bin/python -m pytest tests/test_robinhood_pump_shadow.py tests/test_robinhood_pump_v2_shadow.py tests/test_evm_swap_ws.py tests/test_onchain_pool_discovery.py -q` green.
- Read access to `/opt/aria-data/shadow.db` (readonly) for the live checks below.

## SC-001 -- discovers and prices with DexPaprika/GeckoTerminal unreachable

DexPaprika is already unreachable today (system_issues #269, 402 on ~99.8% of calls) -- this scenario can be validated against real production conditions without any artificial network block.

```bash
tail -n 200 /opt/aria-data/solana-robinhood-shadow/shadow_persistent.log \
  | grep "onchain_pool_discovery\[robinhood\]"
```

**Expected**: `qualified_this_cycle` is no longer stuck at 0 across every recent line -- at least some cycles show a qualified candidate, with no `dexpaprika` warning lines interleaved for the robinhood chain in the same window.

## SC-002 -- zero fabricated prices, traceable to a real on-chain event

```bash
sqlite3 -readonly /opt/aria-data/shadow.db \
  "SELECT COUNT(*) AS total, SUM(CASE WHEN entry_tx_hash IS NULL THEN 1 ELSE 0 END) AS untraced
   FROM robinhood_pump_shadow_log WHERE detected_at >= datetime('now', '-1 day');"
```

**Expected**: `untraced` is 0, or every non-zero row is individually explained (cold-reserve-read entries, per data-model.md's validation rule) rather than silently accepted.

## SC-003 -- zero live-call references to GeckoTerminal/DexPaprika

```bash
grep -n "dexpaprika\.\|geckoterminal_client\.\|GeckoTerminalClient\." \
  src/aria_core/robinhood_pump_shadow.py src/aria_core/robinhood_pump_v2_shadow.py
```

**Expected**: no match beyond a type-only import line (e.g. `from aria_core.services.geckoterminal import TrendingPool, PoolSnapshot, OHLCVResult`) -- any remaining line must be a bare import statement, never a call.

Also confirm the transitive dependency this research pass actually found:

```bash
grep -n "dexpaprika\." src/aria_core/services/onchain_pool_discovery.py
```

**Expected**: zero matches (the reserve/price/symbol fallback calls found in research.md are gone).

## SC-004 -- threshold quantity review, worked example

Pick one real, currently-open or recently-closed Robinhood Chain pool. Compare:

1. Its `reserve_usd` as it was resolved by the OLD code path (DexPaprika-backed, from a `fresh_launch_pretrade_gate_log` row logged before this feature shipped).
2. Its `reserve_usd` as resolved by the NEW direct on-chain read, for the same pool at as close a timestamp as practically available (a live re-read if the pool still exists, or the last websocket-derived reading pre-migration otherwise).

**Expected**: the two figures agree within normal indexing-latency noise (a few percent, consistent with DexPaprika's own documented ~15s free-tier staleness) -- not a structural mismatch. Document the pair of numbers in the feature's HANDOFF entry. If they diverge beyond latency noise, STOP and report to the operator rather than silently adjusting `MIN_LIQUIDITY_USD`/`MIN_LIQUIDITY_USD_DAY_ZERO`.

## FR-009 -- subscription cap holds under real load

```bash
tail -n 500 /opt/aria-data/solana-robinhood-shadow/shadow_persistent.log \
  | grep -c "subscription cap reached\|blocked_pocket_cap\|skipped: at capacity"
```

**Expected**: the process log shows the cap's `skip/defer` path firing under genuine load (or, if traffic never reaches the 150-pool cap in the observed window, confirm via a bounded synthetic test in `test_onchain_pool_discovery.py` that the skip path is reachable and never silently drops without logging).
