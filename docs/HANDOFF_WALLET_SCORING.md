[CODE] Sujet    : Plafond de couverture à 50 tokens pour la file d'attente (item #149) -- même cap que /walletscore
Date : 2026.07.27 / Probleme : suite directe de l'item #119 (débit de la file corrigé) -- opérateur observe que la file avance quand même très lentement (296/301 wallets jamais tentés), propose de limiter à "50 tokens par valeur $". Vérifié dans le code : `_select_tokens_for_deep_analysis` ne trie PAS par valeur $ (round-trip clos + récence + fréquence de trades), et un tri par valeur $ nécessiterait un appel prix par token juste pour trier, annulant le gain recherché. Vrai goulot identifié : `run_wallet_scan_queue_cycle` vise `full_coverage` = couverture EXHAUSTIVE (tous les tokens jamais trouvés, jusqu'à 1067, ~19h+/wallet actif au pire cas) alors que la commande manuelle `/walletscore` se contente déjà de `WEIGHTS.max_tokens_analyzed=50` (déjà bien trié) sans jamais viser l'exhaustivité.
Solution : nouveau paramètre `coverage_target: int | None = None` sur `score_wallets()` -- `full_coverage` devient vrai dès `min(total_found, coverage_target)` au lieu de toujours `total_found`. Défaut `None` = comportement historique inchangé pour tout appelant existant (dont `/walletscore`, qui n'en bénéficie pas explicitement mais n'est jamais régressé). `wallet_scan_queue.py` passe `coverage_target=WEIGHTS.max_tokens_analyzed` sur ses 3 appels (monitoring, boucle catch-up, appel final) -- réutilise le MÊME tri déjà en place (round-trip + récence), change seulement QUAND "assez de données" est déclaré, jamais QUELS tokens sont analysés en premier. Messages "couverture complète" corrigés pour rester honnêtes (`_format_card_for_prompt`/`format_wallet_score_card_lines`/notification Telegram) -- distinguent désormais "couverture jugée suffisante (plafonnée)" de "couverture complète (100% réel)", jamais le mot "complète" à tort quand le plafond a limité la couverture avant la fin réelle. Gain estimé : un wallet moyen (577 tokens) passe de ~58 sous-lots de 10 à ~5 pour atteindre full_coverage -- ~11x plus rapide par wallet. `services/smart_money.py`/`services/wallet_scan_queue.py` -- tests dédiés (`test_smart_money_wallet_scoring.py`, `test_wallet_scan_queue.py`), full suite + `test_coherence.py` à confirmer avant commit.
