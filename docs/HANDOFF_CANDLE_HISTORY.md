[CODE] Subject : new module — FIFO candle history per (chain, pool_address, timeframe), passive hook wired into `_fetch_candles`
Date : 2026.08.11 / Problem : before this module, every candle fetch (`_fetch_candles` in `momentum_entry.py`) only lived in a 60-second in-memory cache — no series ever accumulated enough depth for a real trend signal or a reproducible backtest, and ~92% of tokens ARIA ever scans (measured live this session: 1945 distinct tokens/13 days, only ~8% generate any trade) left zero trace once rejected. Operator proposal (11/08, long design negotiation, real numbers verified at every step — DB size, token/day counts, GeckoTerminal throttle history including the documented 6-day live-lock incident): keep a bounded history fed organically by what the pipeline already fetches, plus (not yet built) a dedicated collector cycle over `services/goplus_watchlist.py` ("the watchlist" — the one and only list this bare term refers to on this project, see `feedback_watchlist_means_goplus_watchlist.md`).
Solution : `candle_history.py` — `record_candles()`/`get_history()`, real timeframe INFERRED from the candles' own median spacing (`infer_timeframe()`, never trusted from the caller's `mode` string, since the fetch ladder's chosen rung isn't exposed at that level) so a degraded fetch (e.g. "standard" landing on 4H instead of 1D) never corrupts a series with mixed granularities. Per-timeframe FIFO cap (`FIFO_CAP_BY_TIMEFRAME`: 1D/4H/1H/15M=1000, 30M=500), 5M explicitly excluded from persistence (v9's own trading behavior unaffected — operator decision, "deja le 5 minutes on peut lenlever sa economisera des bougie"). Deliberately NO purge by staleness/age (explicit operator decision: "elle doit tenir le registre des bougies pour tous... quelle y trade ou non") — only the per-key FIFO cap bounds depth, unbounded in the number of distinct keys. Schema deliberately minimal (2-agent Workflow audit finding: no `provider`/`degraded`/`symbol`/`inserted_at` columns, none has a real Phase-1 consumer). Wired as a passive hook right after the existing `candle_staleness_shadow` observation in `_fetch_candles` — independent try/except (a `candle_history` failure must never break a real fetch, same best-effort contract as every other shadow module), zero extra network call.
`candle_history.py` (new)/`momentum_entry.py`/`tests/test_candle_history.py` (new, 14 tests)/`tests/test_momentum_entry.py` (2 new tests: hook invoked with correct args, hook failure never blocks a real fetch). Full suite green (9884 passed, 17 skipped). Not deployed yet.
