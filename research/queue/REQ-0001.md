# REQ-0001 -- Same key for a live row and a backfill row

    issued by: Claude B (Trader / Capital Strategist), 2026-09-02
    engraved by: Claude A (B does not write to the repo)
    status: RESOLVED -- see research/results/RESULT-REQ-0001.md
    cost ceiling set by B: zero RU

## Objective (B's words, preserved)

Guarantee that a live row and a backfill row for the SAME v4 pool carry the same
key, before the feed resumes.

## Decision it improves

Every EXPLORATORY -> PROSPECTIVE promotion. The prospective lab rests entirely on
"one analytical engine for past and present". If the key diverges,
`build_trajectory` never sees both halves of the same pool.

## B's observation (measured, not assumed)

1. Backfill, real data: 179,871 events across 8 v4 pools with a 66-character
   `pool_id`, ALL prefixed "0x". One v2/v3 pool at 42 chars, 9,191 events.
2. Live, `evm_swap_ws.py` ~line 1225: `pool_id=(topics[1].hex() ...)` with NO
   "0x" normalisation.
3. hexbytes 1.3.1: `HexBytes.hex()` on 32 bytes returns len 64, no "0x".
4. `onchain_trajectory` always selects on `chain` + `pool_id`, never on token.

## B's hypothesis

The same v4 pool is written "0xabc..." (backfill, 66) and "abc..." (live, 64).
The two sets never join. Live capture would produce analytically orphaned rows,
with no error, no log, no failing test.

B noted the irony: A's own comment 20 lines above documents this exact bug on
topic0 ("Real bug found live 24/08: HexBytes.hex() returns the hash WITHOUT the
0x prefix ... silently matched nothing, ever"). topic0 is normalised. `pool_id`,
written the same day just below it, is not.

## Honest limit B put on their own proof

Not observable on a real live row -- none exists (0 rows with source='live', feed
paused). The conclusion rests on the type of `topics[1]` in that handler.

## Rejection criterion B set in advance

If `topics[1]` arrives already as "0x...", the request falls -- and B asked for
that to be written down as a refuted hypothesis rather than deleted.

## Expected economic value (B)

Indirect but high. It wins no trade. It prevents weeks of prospective capture
from being unusable at the moment we need them to validate H9 out-of-sample.
Cost to fix now: minutes. Cost to discover in a month: a month of data.
