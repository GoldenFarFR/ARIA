# SPEC-0001 -- Operational definition of an economically tradable result

    issued by: Claude B (Project Director / Capital Strategist), 2026-09-02
    engraved by: Claude A. B's text preserved; A's corrections are marked as such.

A record traverses a cascade. At each stage it can be disqualified, and a
disqualification is NEVER a WIN nor a LOSS. Same principle as unknown != zero.

    E0 IDENTIFIABLE   canonical pool_id resolvable, chain known, token resolvable
                      -> UNIDENTIFIABLE
    E1 RECONSTRUCTIBLE T_entry < T_exit; entry price from data <= T_entry; exit
                      price from data <= T_exit; no later data enters the entry
                      -> NON_RECONSTRUCTIBLE
    E2 OBSERVABLE     depth known at T_entry AND at T_exit (never the final
                      reserve carried backwards); price freshness <= regime bound
                      -> NON_OBSERVABLE
    E3 EXECUTABLE AT SIZE S  entry impact + exit impact <= 10% (ARIA's absolute
                      rule); size <= entry reserve bound; exit value <= exit
                      reserve bound -> NON_EXECUTABLE_AT_S (per size, not absolute)
    E4 NET            return after modelled slippage, fees, gas
    E5 CAPACITY       S* = largest size where E3 holds and E4 stays positive
    E6 PROSPECTIVELY VALIDATED  observed forward, never reconstructed

## Three quantities never to be confused

    MARKET_RETURN         what the price did. Computable from E1. Size-independent.
    EXECUTABLE_RETURN(S)  what a position of size S would have obtained. Needs E3.
    CAPACITY              S*. The measure ARIA completely lacks today.

## Thresholds set by B, with A's correction applied

- Round-trip impact <= 10%: taken from ARIA's engraved slippage rule, never a
  tool default.
- **A's correction, verified in code (2026-09-02):** `reserve_usd` is the pool's
  TOTAL liquidity, both sides combined, and `_apply_price_impact_and_fee` already
  divides by 2 to approximate one side's depth. B's "size <= 5% of reserve"
  therefore applies to ONE SIDE, i.e. **2.5% of `reserve_usd`**, and the comfort
  threshold becomes 0.5%, not 1%. B's factor-of-2 question was well founded.
- Price freshness <= 5s in fast regime, <= 60s otherwise. **Assumed conservative
  hypothesis, not a measurement**, to be recalibrated once a sample exists. It
  comes from the 22/08 incident (entry quoted on a 36s-stale price, trailing stop
  fired on a phantom peak).

## Honest limit of the whole measurement (B's words, to be printed in every report)

`reserve_usd` is a PROXY for depth, not depth. On concentrated-liquidity v4 pools
the depth actually available near the current price is <= total reserve, sometimes
far below. The filter is therefore OPTIMISTIC: it cannot reject a trade wrongly,
it can only let through one that is in reality not executable. So everything it
rejects is certainly rejectable, and the PnL it produces stays an UPPER bound.
Decidable on that basis, provided it is never presented as anything but a ceiling.

## Verification B ran on the two known cases before sending

- x4 with $4 reserve: the smallest size considered ($2) is 50% of the reserve.
  Rejected at E3 on entry, at every size. -> NON_EXECUTABLE, removed from alpha.
- x1972 with $8,434 entry reserve: a $25 position is only 0.30% of reserve, so
  ENTRY passes E3. The EXIT kills it: $25 x 1972 = $49,300 to extract from a pool
  of that size. Rejected at E3 on exit. -> MARKET_RETURN = +197,100%,
  EXECUTABLE_RETURN = N/A, CAPACITY ~ a few dollars.

Intended behaviour: the trade does not disappear, it changes category. It stops
being strategy alpha and becomes information about what the market offered
without our being able to take it.

## Size ladder (B's list merged with the operator's)

    $2 / $10 / $25 / $50 / $100 / $250 / $1000

The first five are real ARIA bounds (Robinhood per-trade cap, CDP pilot floor and
hard cap, home-wallet target). $1000 is there to see where it dies.

## Two mandatory readings

(a) variable population -- each rung on the trades executable at that rung, n shown.
(b) constant population -- every rung on the SAME subset, the one executable at the
    largest size.

Without (b), a drop in return is indistinguishable from a change of sample. The
gap between (a) and (b) measures how much of the apparent edge comes from
selecting micro-pools.

Every published figure carries, without exception: n_total, n_executable, size S,
without-top2, without-top5, and the number of distinct CLOSURE days.

## A's finding that changes the build, not the spec

The impact model already exists: `_apply_price_impact_and_fee` (constant product,
returns `None` rather than a fabricated number when depth cannot absorb the size),
present in all three pockets. It is calibrated at `SIMULATED_TRADE_SIZE_USD = 0.1`
-- ten cents, resized from $20 on 17/08 by explicit operator decision. So B's
rejection criterion is partly triggered: the model is not missing, it is
calibrated on an economically meaningless size. REQ-0002 becomes a replay of the
existing model at the seven rungs, not a construction.
